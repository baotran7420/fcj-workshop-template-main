Event 3

Reflection Report on “AWS FCAJ Agent Forge”

Purpose of the Event

AWS FCAJ Agent Forge is an event that provides participants with an opportunity to learn about Agentic AI, AI Agent architecture, and the deployment of Agent components on AWS.

The event focuses on the evolution from Generative AI to Agentic AI, while introducing important components of an Agent architecture such as Memory, Observability, and Policy, as well as various tools that can extend the capabilities of an Agent.

In addition to the theoretical session, the event includes a Hands-on Lab, allowing participants to set up a development environment, install the required tools, and practice deploying Agent components in a real-world AWS environment.

The main objectives of the event are:

  • Understand the evolution from Generative AI to Agentic AI.
  • Understand the architecture and key components of an AI Agent.
  • Learn about the role of Memory in maintaining user information and context.
  • Understand Observability and how to monitor Agent activities.
  • Learn about Policy and access control mechanisms for Agents.
  • Explore tools that can extend Agent capabilities.
  • Understand the process of deploying Agent components on AWS.
  • Gain practical experience in deploying Agent components in a real-world environment.
  • Keep up to date with AI technologies through the First Cloud AI Journey (FCAJ) community.

Speakers

  • Nghia Tran – Agentic SA.
  • Pham – Cloud Consultant, G-AsiaPacific Vietnam.

Key Topics

1. Theoretical Session - Nghia Tran

The theoretical session was presented by Nghia Tran - Agentic SA, focusing on the architecture and core components of an Agentic AI system.

1.1. Agentic AI System Architecture

Nghia Tran introduced the evolution from Generative AI to Agentic AI and explained how different components work together to build a complete Agent system.

The main topics included:

  • The evolution from Generative AI to Agentic AI.
  • The overall architecture of an Agentic AI system.
  • The role of different components within an Agent architecture.
  • The importance of deeply configuring Agent components.
  • An introduction to concepts such as Memory, Observation, and Engineering.

From this presentation, I understood that Agentic AI is not only focused on the content-generation capabilities of Generative AI. Instead, it extends the capabilities of AI systems through multiple components and tools that allow Agents to perform more complex tasks.

1.2. Memory - Agent Memory

Memory is one of the key components of an Agent discussed during the theoretical session.

Memory acts as a bridge between short-term conversations and long-term knowledge, allowing the Agent to maintain and use relevant information during interactions with users.

The main topics included:

  • The role of Memory in an Agentic AI system.
  • Maintaining information across conversations.
  • Remembering user preferences.
  • Remembering information related to users.
  • Supporting personalized user interactions.

Through this topic, I gained a better understanding of how Memory helps an Agent maintain context and use previously known information to provide more appropriate responses to users.

1.3. Observability - Monitoring Agent Activities

Observability was introduced as an important component for operating and monitoring an Agent system.

The main components of Observability include:

  • Log: Records activities and events occurring within the system.
  • Trace: Tracks the processing flow of a request.
  • Metric: Provides measurements used to evaluate system performance.

Observability helps administrators:

  • Monitor Agent performance.
  • Detect errors during processing.
  • Analyze system activities.
  • Evaluate system operation.
  • Optimize the system.

This topic helped me understand that building an Agent is not only about implementing its functions. The system must also provide sufficient observability to ensure stable operation in a real-world environment.

1.4. Policy - Permissions and Security Policies

Policy was introduced as a mechanism for defining permissions and security policies for an Agent.

The main topics included:

  • Understanding the role of Policy in an Agent system.
  • Defining permissions for the Agent.
  • Controlling the actions that the Agent is allowed to perform.
  • Limiting the Agent’s scope of operation.
  • Learning about the use of Seda for defining Agent policies.

Through this topic, I gained a better understanding of the importance of controlling Agent permissions and behavior, especially when the Agent is allowed to interact with multiple tools or services.

1.5. Tools Supporting Agents

In addition to the core components, the theoretical session introduced several tools that can be integrated into an Agent to extend its capabilities.

Browser

Browser allows the Agent to navigate and interact with content on the web.

Code Interpreter

Code Interpreter allows the Agent to execute code and support tasks that require calculations or programmatic processing.

Payment

Payment was introduced as a component that can be integrated to support payment functionality within an Agent system.

These tools demonstrate how the capabilities of an Agent can be extended depending on the requirements and objectives of a particular system.

2. Hands-on Lab - Pham

The Hands-on Lab was conducted by Pham - Cloud Consultant, G-AsiaPacific Vietnam, focusing on setting up the development environment and deploying Agent components on AWS.

2.1. Setting Up the Development Environment

The Hands-on Lab began with instructions on preparing the required environment for developing and deploying Agentic AI applications.

The practical activities included:

  • Setting up the development environment.
  • Checking the required components.
  • Preparing the dependencies needed for the hands-on session.
  • Preparing the tools required to deploy the Agent.

Preparing the environment ensures that all required tools and dependencies are available before starting the deployment process.

2.2. Installing the Required Tools

During the Hands-on Lab, participants were guided through the installation and use of tools required for Agent development and deployment.

The main tools included:

  • AWS CDK: Used to define and deploy infrastructure on AWS.
  • Agent CLI: Used to interact with and manage Agent-related components.
  • Required dependencies for the development environment.

Through this session, I became more familiar with the process of preparing development tools before deploying an Agentic AI system.

2.3. Deploying the Memory Component

One of the main practical activities was deploying the Memory component into a real system.

The practical steps focused on:

  • Preparing the deployment environment.
  • Installing and configuring the required dependencies.
  • Using the provided development tools.
  • Performing the deployment process.
  • Deploying the Memory component into the system.
  • Checking the deployment results.

This hands-on activity helped me understand how theoretical knowledge about Memory can be applied to the actual deployment of an Agentic AI component on AWS.

Conclusion

AWS FCAJ Agent Forge was a valuable experience that helped me gain a better understanding of Agentic AI from both theoretical and practical perspectives.

Through the presentation by Nghia Tran - Agentic SA, I learned about the evolution from Generative AI to Agentic AI, Agent architecture, and important components such as Memory, Observability, and Policy. I also learned about tools that can extend Agent capabilities, including Browser, Code Interpreter, and Payment.

The Hands-on Lab, conducted by Pham - Cloud Consultant, G-AsiaPacific Vietnam, allowed me to experience the practical deployment process. I learned how to set up the development environment, install dependencies, work with AWS CDK and Agent CLI, and deploy the Memory component into the system.

Through this event, I realized that building an Agentic AI system involves more than just selecting an AI model. It also requires careful consideration of architecture, Memory, Observability, Policy, supporting tools, and deployment processes.

The knowledge gained from this event provides a useful foundation for my continued learning, research, and development of AI projects on AWS. Participating in the First Cloud AI Journey (FCAJ) community also gives me opportunities to continuously update my knowledge and follow the rapid development of Agentic AI technologies.
